# ADR: 工厂实拍采用 Codex + 剪映音频 + FFmpeg QC 混合路线

- 状态：Accepted
- 日期：2026-07-25
- 适用类型：`factory_demo`
- 决策来源：`factory_ab_img5667_20260724_01` 真实 A/B 结果与用户听审
- 不适用类型：`video_diary`

## 背景

`factory_ab_img5667_20260724_01` 使用同一条 `IMG_5667.MOV`、同一剪辑蓝图、同一标题、同一字幕和同一 BGM 比较了两条音频处理路线：

- 路线 A：Codex/Python/FFmpeg 确定性时间线，当前实际测试的降噪器为 FFmpeg `afftdn`；
- 路线 B：相同共同母版进入剪映专业版 7.9.0，启用剪映原生音频降噪后导出。

用户已明确确认：本次剪映原生降噪的人声清晰度明显优于当前 `afftdn` 结果。这个结论只覆盖本次素材和已经实际测试的处理参数，不外推为“剪映优于所有开放降噪模型”。

## 决策

工厂实拍 V1 采用混合生产路线：

1. Codex 负责语义理解、逐字字幕、同步区域、动作锚点和共同剪辑蓝图；
2. FFmpeg/Python 负责确定性画面时间线、四轨资产、可重复渲染和自动质量检查；
3. 剪映专业版只负责原生人声降噪与最终音频混合导出；
4. 剪映画面轨、内容顺序、标题和字幕全部锁定，不允许再次自动剪辑或自由设计；
5. 路线 A 保留为快速预览、无人值守降级和剪映不可用时的业务连续性链路。

本阶段不引入 `video-use`、HyperFrames 或 Remotion。DeepFilterNet3 与 ClearerVoice 仅列入备用研究项，不阻塞混合路线生产化。

## A/B 真实证据

### 路线 B 母版

- 指定母版：`experiments/factory_ab_img5667_20260724_01/chatgpt_upload_bundle/02_剪映正式版_route_b.mp4`
- SHA-256：`671387484343c614fb89bc488943b4d4bad88edaf9d23747b633f1e2872c6e99`
- 规格：1080×1920、60 fps、AAC 48 kHz、双声道、28.350 秒
- 剪映直接导出证据：`route_b_jianying/finaljianyingnativedirect.mp4`
- 剪映版本：7.9.0 build 366
- 原生降噪 UI 证据：`route_b_jianying/screenshots/41_native_denoise_enabled_rhythm_v2.png`
- 成功导出证据：`route_b_jianying/screenshots/43_export_complete_rhythm_v2.png`

`02_剪映正式版_route_b.mp4` 是剪映原生降噪母版的交付版本。`finaljianyingnativedirect.mp4` 是剪映直接导出的 44.1 kHz 证据文件；`02` 是将该母版整理为生产交付规格后的版本。

### 03 与 02 的关系

`03_候选01_剪映降噪.mp4` 对应盲测候选 01，其私有映射明确指向 `route_b_jianying`。它是基于路线 B 母版生成的响度/交付标准化副本，不是新的剪辑路线，不计入路线数量，也不能作为独立算法效果证据。

### 路线 A

- 降级预览：`experiments/factory_ab_img5667_20260724_01/chatgpt_upload_bundle/04_候选02_开放工具链.mp4`
- 实际测试：FFmpeg `afftdn` 和一个 `anlmdn` 候选；
- 正式路线 A 采用的是保守 `afftdn` 参数；
- DeepFilterNet3 和 ClearerVoice 未安装、未运行、未形成 A/B 证据。

因此，“路线 B 优于路线 A”的准确表述是：本次素材中，用户确认剪映原生降噪的人声清晰度优于当前 FFmpeg `afftdn` 路线。

## 为什么不让剪映接管共同剪辑

共同剪辑需要可审计、可重复、可做机器校验：

- 每个剪点必须能追溯到 `edit_plan.json`；
- 人物正面讲话必须保持音画同步；
- 平板、看板和设备镜头需要按 `C_AUDIO_FREE` 处理；
- 点击、滑动和页面切换需要按 `D_ACTION_LOCKED` 保留完整；
- 字幕必须来自最终保留人声，禁止总结、改写和专业词替换；
- 同一共同蓝图必须能产生剪映母版和路线 A 降级版。

这些约束由确定性时间线更可靠地保证。剪映只处理其已被真实听审证明有优势的音频环节。

## 剪映风险和控制

已知风险：

- GUI 控件和布局随版本变化；
- 登录、会员权益、弹窗和素材加载会阻塞流程；
- 自动更新可能改变工程格式或原生效果；
- 草稿格式在当前版本中加密，不能假设可以稳定直接改 JSON；
- “工程打开”或“看到导出窗口”不等于实际导出成功。

控制措施：

- 锁定并记录 7.9.0 build 366；
- 保持用户现有登录状态，不在脚本中保存凭据；
- 使用固定四轨模板和稳定素材文件名；
- 自动化优先通过控件/视觉状态确认，不只依赖固定坐标；
- 每个关键步骤记录时间、状态、失败、重试和截图；
- 只有导出文件存在、可完整解码、规格通过，才标记 `export_succeeded=true`；
- 自动更新控制只记录为人工环境要求，不擅自修改系统或应用更新策略。

## 固定四轨接口

共同蓝图必须输出：

- `picture_master_no_audio.mp4`：只含画面、标题和共同字幕；
- `dialogue_raw.wav`：最终保留人声，不做路线专属降噪；
- `ambience.wav`：连续工厂环境底声；
- `bgm.wav`：独立立体声 BGM；
- `subtitles.ass`、`title.png`、`edit_plan.json`、`sync_zones.json`、`action_anchors.json`。

剪映固定轨道：

- V1：`picture_master_no_audio.mp4`
- A1：`dialogue_raw.wav`，启用剪映原生音频降噪
- A2：`ambience.wav`
- A3：`bgm.wav`

不允许剪映自动字幕覆盖共同字幕，不允许改变内容、镜头、标题、字幕、滤镜或转场。

## 人工审核边界

以下字段未经逐句人工听审不得由 `null` 自动改成 `0` 或 `true`：

- `audio_subtitle_mismatch_count`
- `word_loss_count`
- `visible_lip_sync_error_count`
- `perceptual_continuity_pass`

本次用户听审只足以确认：

- `denoise_effective: true`
- `denoise_human_review_pass: true`

字幕逐句匹配、吞字、口型、整体连续性仍需独立人工复核。

## 后果

优点：

- 保留 Codex/FFmpeg 的确定性与可审计性；
- 使用已被用户证实更好的剪映人声处理；
- 剪映不可用时仍有可交付的路线 A；
- 不扩大依赖，降低当前 V1 的系统复杂度。

代价：

- 生产仍依赖一个受监督 GUI 环节；
- 剪映版本和会员状态需要运维；
- 四轨工程比单条混音母版多一个素材管理层；
- 在自动化达到 9/10 成功率前，工厂实拍 V1.0 不能判定 Go。

## 当前验证缺口

截至 2026-07-25，授权原始素材不可用。本机已有的共同母版仅包含 2.18 秒完整平板动作区，不足以证明“连续平板画面内至少两处 0.5 秒以上停顿”的新 `C_AUDIO_FREE` 验收条件。该项必须在原素材恢复后用真实连续操作区段补测，不能用旧成片或冻结帧冒充通过。

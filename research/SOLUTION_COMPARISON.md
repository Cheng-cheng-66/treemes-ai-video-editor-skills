## 2. 底层组件职责与阶段

| 组件 | 职责 | 必须/替换/后期 | 采用判断 |
|---|---|---|---|
| Codex | 建设、调试、编排、日志诊断、例外修复 | 必须（研发层） | 不作为唯一常驻运行时 |
| Python 3.11 | 业务规则、模型适配、状态机、API/CLI | 必须 | 主编排语言 |
| FFmpeg | 剪切、合成、字幕、音频、转码、导出 | 必须 | 唯一 V1 核心媒体执行器 |
| ffprobe | 媒体/流/元数据清点 | 必须 | 所有任务第一步 |
| SQLite | 任务、素材、区间、审核、日志 | 必须 | V1 单机足够；V2 可换 PostgreSQL |
| FunASR/Paraformer | 中文 ASR、热词、字符时间戳 | 可替换但必须有一个 ASR | 与 faster-whisper 用公司样本 A/B |
| faster-whisper | 通用多语、本地高效 ASR | 可替换但必须有一个 ASR | 跨语种/生态强 |
| WhisperX | 逐词对齐、说话人 | V1.1 后 | 先证明 V1 时间码不够再引入 |
| LLM | 结构分析、删除/保留候选、理由 | 必须但可降级 | Structured Output；无权直接删原片 |
| OpenCV | 抽帧、质量评分、跟踪 | V1 可选/V2 必须 | 工厂/Vlog/居中 |
| PySceneDetect | 镜头边界、EDL/OTIO | V1.1/V2 | 工厂和专业交接 |
| MediaPipe/YOLO | 人脸/人物/设备对象 | V2 | 需样本与定制标签 |
| Remotion | 动态字幕、关键词、品牌模板 | V1.1 | V1 先用 ASS/FFmpeg |
| Web 审核页 | 接受/拒绝/恢复、预览、批注 | 必须，可从静态 HTML 起 | 决定能否安全生产 |
| 本地任务队列 | 重试、并发、资源限制 | V1 简版/V1.1 正式 | 不建议一开始上复杂分布式系统 |
| OTIO/FCP XML/EDL | 人工继续编辑 | V1.1 | 避免绑定单个 NLE |
| Premiere UXP/DaVinci API | 专业精修适配 | V2 | 根据团队实际软件二选一 |
| 剪映适配器 | 导出草稿或辅助导入 | V2 可选 | 永不成为唯一工程格式 |

## 3. 三套完整架构

### 架构 A：最低成本 V1

```text
只读素材目录
  → Python CLI
  → ffprobe
  → ASR A/B 选定引擎
  → 静音/重复/重录候选
  → LLM JSON 决策
  → HTML 审核
  → FFmpeg 预览
  → 人工确认
  → FFmpeg 正式 MP4 + SRT + manifest
```

| 项目 | 结论 |
|---|---|
| 开发难度 | 中，1–2 周样机 |
| 运行成本 | 低；本地计算 + 少量 LLM |
| 质量 | 口播粗剪可用，包装基础 |
| 主要优点 | 快、审计清楚、原片安全 |
| 主要缺点 | 审核交互与动效有限 |

### 架构 B：推荐的持续生产版

```text
上传/监控目录
  → FastAPI
  → SQLite/PostgreSQL
  → 持久任务队列
  → ASR/Scene/CV Workers
  → LLM 决策与规则引擎
  → Web 波形/文本/缩略图审核
  → FFmpeg 粗剪 + Remotion 包装
  → 自动质检
  → MP4/SRT/OTIO/FCP XML
```

| 项目 | 结论 |
|---|---|
| 开发难度 | 中高，4–8 周稳定内测 |
| 运行成本 | 低到中，可缓存和本地优先 |
| 质量 | 口播高、访谈中高、工厂候选中 |
| 主要优点 | 可恢复、可扩展、可批量、可人工接手 |
| 主要缺点 | 需要正式前后端/任务/模型工程 |

### 架构 C：数字员工终局

```text
多入口/业务触发
  → 不可变对象存储与素材哈希
  → 镜头/文本/人物/设备/授权索引
  → 工作流编排器 + Worker 池
  → ASR/CV/VLM/LLM
  → 多候选版本
  → 人工审批/升级
  → Remotion + Premiere/DaVinci
  → 技术 QC + 内容/合规 QC
  → 独立发布审批
  → 反馈集/评测/成本监控
```

| 项目 | 结论 |
|---|---|
| 开发难度 | 高，3–9 个月渐进演进 |
| 运行成本 | 中高 |
| 质量 | 取决于素材治理、栏目规则和人工审核 |
| 主要优点 | 跨场景、长期积累、可度量 |
| 主要缺点 | 数据治理、运维和模型漂移复杂 |

## 4. 场景决策矩阵

| 场景 | 现在可全自动的部分 | 只能粗剪 | 必须人工 | 自动化成熟度 | 版本 |
|---|---|---|---|---:|---|
| 老板口播 | 转写、静音候选、字幕、品牌基础包装、导出 | 口误/重复/节奏 | 事实、术语、最终成片 | 4/5 | V1 |
| 工厂现场 | 切镜、质量评分、标签/检索 | B-roll 匹配与排序 | 安全、保密、真实性 | 2.5/5 | V2 |
| 客户案例 | 转写、说话人、章节/短片候选 | 长片结构、观点组合 | 数据、授权、语境 | 3.5/5 | V1.1 |
| Vlog | 镜头分类、质量/节拍、字幕 | 初步叙事排序 | 风格、情绪、音乐 | 2/5 | V3 |

## 5. 成本口径

- 本地开源：软件费低，但有模型下载、算力、工程、运维和人工审核成本。
- LLM：主要处理转写文本与少量帧描述，按 Token 计费；必须缓存同一转写/镜头结果，避免重跑。
- VLM：只在低置信度片段、工厂镜头和 B-roll 候选上调用；不应整片逐帧送云。
- Remotion：本地渲染主要是机器时间；云/Serverless 渲染另计；企业许可需按官方条款核对。
- Premiere：订阅；DaVinci Studio 官方本次价格 US$295 一次性。
- SaaS：常见按处理分钟、媒体小时或 AI credits；适合基准，不适合核心成本模型。

## 6. 最终选择

1. **V1 底座：Python + FFmpeg/ffprobe。**
2. **中文理解：FunASR/Paraformer 与 faster-whisper 用真实样本 A/B，接口可替换。**
3. **决策安全：规则/LLM 只生成可恢复候选，人工审核是硬门。**
4. **包装：V1 用 ASS/FFmpeg；V1.1 才加 Remotion。**
5. **人工续编：先导出 OTIO/FCP XML/EDL；根据团队工具再做 Premiere UXP 或 DaVinci。**
6. **剪映：保留为可选导入/人工精修，不做核心数据库和唯一工程格式。**

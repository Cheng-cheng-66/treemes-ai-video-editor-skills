# V1.0 推荐方案

> 版本目标：用最小范围验证“中文口播自动粗剪是否真实节省时间且不造成不可恢复误删”。  
> 调研日期：2026-07-23。

## 1. 核心场景

单人中文老板口播：

- 输入：3–10 分钟 MP4/MOV；
- 内容：停顿、重录、重复表达、少量口误；
- 输出：1080×1920 H.264/AAC 预览与正式版；
- 包装：中文字幕、Logo、固定片头片尾、轻量 BGM；
- 决策：所有删除可解释、可审核、可恢复。

## 2. 为什么选择它

- 语音是主要信息源，ASR + 时间码可以覆盖大部分粗剪工作；
- 品牌包装规则固定，容易自动化和验收；
- 误删风险可以通过审核/恢复机制控制；
- 能用短周期和明确指标证明是否节省人工；
- 成功后技术资产可复用于客户访谈长转短。

不选择工厂 B-roll 作为 V1，因为它同时需要素材治理、视觉标签、语义检索、合规和导演判断，变量过多；不选择 Vlog，因为叙事与审美难以客观验收。

## 3. 功能范围

### 必须实现

1. 只读接入、哈希、任务目录；
2. ffprobe 媒体信息；
3. 中文转写 JSON + SRT；
4. 静音/长停顿、填充词、重复/重录候选；
5. 剪辑决策清单 JSON；
6. 人工接受、拒绝、恢复；
7. FFmpeg 粗剪与音频切点淡化；
8. 中文字幕、Logo、片头片尾、9:16；
9. 预览版/正式版；
10. 输入输出时长、删除清单、命令、版本、日志；
11. 阶段缓存与失败恢复。

### V1 可选

- 简单固定 BGM 和 sidechain/ducking；
- 人脸中心的固定裁切建议；
- 静态 HTML 审核页替代完整前端；
- `auto-editor` 作为静音检测结果对照。

## 4. 技术架构

```text
Codex
  ├─ 编写/维护/测试代码
  ├─ 根据日志修复失败
  └─ 不进入无人审核发布链

只读 source/
  → ingest.py（哈希、任务 ID）
  → ffprobe（media.json）
  → audio.wav
  → ASR Adapter
      ├─ FunASR/Paraformer
      └─ faster-whisper
  → transcript.json + subtitles.srt
  → detectors
      ├─ silence
      ├─ filler
      └─ repetition/retake
  → LLM Structured Output
  → edit_decisions.json
  → review.html / review.json
  → FFmpeg Renderer
  → preview.mp4
  → human approval
  → final.mp4 + manifest.json + logs/
```

### 数据实体

- `assets`：源文件、哈希、媒体信息、只读路径；
- `jobs`：状态、阶段、重试、耗时；
- `transcript_segments`：文本、时间码、置信度、模型版本；
- `edit_decisions`：动作、区间、原因、证据、审核状态；
- `renders`：输入决策版本、命令、输出哈希、QC；
- `audit_events`：谁在何时接受/拒绝/恢复。

SQLite 足以支持 V1。每个阶段使用内容哈希作为缓存键。

## 5. 组件选型

| 组件 | V1 选择 | 理由 |
|---|---|---|
| 编排 | Python 3.11 | 生态完整、易由 Codex 维护 |
| 媒体 | FFmpeg/ffprobe | 稳定、跨平台、可审计 |
| ASR | FunASR/Paraformer 与 faster-whisper A/B 后选一 | 不凭印象选择中文模型 |
| 对齐 | 暂不默认 WhisperX | 依赖复杂；先测 V1 时间码是否满足 |
| 数据库 | SQLite | 单机、可迁移、易备份 |
| LLM | 支持 Structured Output 的可替换 Provider | 生成候选和理由 |
| 审核 | 静态 HTML + JSON 或最小 FastAPI 页面 | 先验证工作流，不做重前端 |
| 字幕 | SRT/ASS + FFmpeg | V1 足够、渲染稳定 |
| 包装 | 固定 PNG/视频素材 + FFmpeg | 不引入 Remotion 双栈 |
| 测试 | pytest + 20 条回归片段 | 防止阈值/模型升级回归 |

## 6. 剪辑决策规则

### 自动可建议删除

- 连续静音 ≥ 1.2s，且两端不是句中自然停顿；
- 明确填充词并有足够前后 margin；
- 连续两段语义高度相似，后一段完整且更流畅；
- 出现“重来/再来一遍/刚才说错了”等重录信号；
- ASR 文本、音频能量和时间顺序共同支持。

### 永远需要人工确认

- 包含数字、价格、客户、性能、承诺、日期；
- 低 ASR 置信度；
- 两个候选版本各有信息；
- 删除后主谓宾或指代不完整；
- 语气/停顿可能承担强调作用。

### 不删除

- <400ms 的自然间隔；
- 句中短吸气；
- 无可靠文本证据的低音量段；
- 仅因模型认为“无聊”的内容。

## 7. 开发步骤

### 第一周

1. 收集 10 条真实口播，总时长 ≥60 分钟；复制到测试工作区，不改原件；
2. 人工标注术语、静音、重录、保留/删除和预期成片；
3. 实现 ingest + ffprobe + manifest；
4. 完成 FunASR/Paraformer 与 faster-whisper A/B；
5. 定义 `transcript.schema.json` 和 `edit_decision.schema.json`；
6. 实现静音候选与最小 FFmpeg EDL 渲染；
7. 用 3 条片跑端到端，记录失败而不是调到单片过拟合。

### 第二周

1. 重复/重录候选与 LLM Structured Output；
2. 审核/恢复；
3. 字幕、Logo、片头片尾、9:16；
4. 阶段缓存、重试、日志和 QC；
5. 20 条代表性片段回归；
6. 对 5 条完整视频做人工耗时对照；
7. 根据验收结果决定继续、改 ASR，或停止。

## 8. 验收标准

以下每项只能判“通过/不通过”：

1. 3–10 分钟 MP4/MOV 可创建任务并产生唯一 ID；
2. 原片处理前后 SHA-256 相同；
3. `media.json` 可解析且关键字段齐全；
4. `transcript.json`/SRT 均生成，时间区间合法；
5. 20 个指定公司术语命中率 ≥90%；
6. 30 个词/句边界误差中位数 ≤300ms，P95 ≤800ms；
7. 10 个 ≥1.2s 静音检出 ≥9 个；
8. 系统不自动删除 <400ms 自然间隔；
9. 所有删除候选 100% 通过 Schema 且含证据；
10. 审核拒绝后，对应区间重新渲染可恢复，边界容差 ±2 帧；
11. 30 个切点中至少 29 个无爆音/明显断裂；
12. 30 条字幕显示区间与语音重叠率 ≥95%；
13. Logo/片头/片尾均出现且配置进入 manifest；
14. 输出为 1080×1920 H.264/AAC，可被 QuickTime 与指定测试端播放；
15. 日志含时长、区间、命令、退出码、版本、耗时且无密钥；
16. 中断渲染后可恢复且不重复 ASR；
17. 指定验收 Mac 上 10 分钟素材预览总耗时 ≤30 分钟；
18. 5 条完整视频的审核/修正平均耗时 ≤现有人工粗剪的 50%；
19. 20 条回归样本连续运行 3 次，确定性结果一致；
20. 代码和配置中不存在自动发布调用或发布凭证。

## 9. 暂不实现内容

- 工厂 B-roll 自动匹配；
- 客户案例完整长片导演；
- Vlog 自动叙事；
- 复杂字幕动画和转场；
- Remotion；
- WhisperX/说话人（除非 A/B 证明必需）；
- YOLO/MediaPipe；
- 剪映草稿写入和桌面自动化；
- Premiere/DaVinci 插件；
- 多机队列、云对象存储；
- 自动发布。

## 10. Go / No-Go 门槛

只有以下条件同时满足才进入 V1.1：

- 20 条回归片通过所有安全/恢复/日志测试；
- 5 条完整视频人工时间节省 ≥50%；
- 没有不可恢复误删；
- 术语和时间码达到验收线；
- 运营人员愿意使用审核界面；
- 单条平均计算/API 成本被记录并在预算内。

任一安全硬门失败则 No-Go；不能用“效果看起来不错”替代指标。
